# @codama/renderers-go

## 2.1.0

### Minor Changes

- [#62](https://github.com/codama-idl/renderers-go/pull/62) [`e684ea6`](https://github.com/codama-idl/renderers-go/commit/e684ea6a7e4b891163ce05e927a725f9862d60b5) Thanks [@sonicfromnewyoke](https://github.com/sonicfromnewyoke)! - ### PDA helpers
  
  Generate `pdas.go` with a `Find<Name>PDA` helper for every structurally distinct PDA in the IDL (from `program.pdas` and inline instruction account defaults). Constant seeds are inlined as byte literals, variable seeds become typed parameters, and PDAs owned by another program derive under that program's id.
  
  ### Jupiter v6 fixes ([#63](https://github.com/codama-idl/renderers-go/issues/63))
  
  - Enums mixing data-carrying and empty variants now compile: empty variants are emitted as `ag_binary.EmptyVariant` fields, and every data enum gets `<Type>_<Variant>` index constants for its `Enum` field.
  - Generated files start with the canonical `// Code generated by @codama/renderers-go. DO NOT EDIT.` marker.
  - Instruction data is serialized with the discriminator declared in the IDL (8-byte Anchor sighash, u32, u8, ...), with no spurious leading byte. `DecodeInstruction` dispatches on the explicit IDL discriminator bytes (not a recomputed sighash or an alphabetical index) and the per-instruction decoder rejects mismatching discriminators.
  - `Build()` and `ValidateAndBuild()` now use pointer receivers and store the instruction pointer in `Impl`, so `Instruction.Accounts()` and the custom codec are always used.
  - Unset optional accounts are passed as the program id (or omitted, per the IDL's `optionalAccountStrategy`) by `GetAccounts()`; `SetAccounts()` accepts on-chain instructions that omit trailing optional accounts and no longer drops remaining accounts.
  - Jupiter v6 added as an e2e project (`e2e/jupiter`), with `e2e/anchor-to-codama.cjs` to convert Anchor IDLs.
  
  ### Other codec fixes
  
  - Default values of data-enum arguments render as Go literals (`Swap{Enum: Swap_Saber}`, or a builder closure for variants with payloads) instead of undefined constants.
  - Scalar enums use the integer size declared in the IDL (`type NonceState uint32` for `repr(u32)` enums) instead of always `uint8`.
  - Remainder-encoded instruction arguments and account fields (bare `string`, `bytes`, and remainder arrays) are written without a length prefix and read to the end of the buffer, matching programs such as Memo. Remainder fields nested inside defined types still go through ag_binary's reflection codec.
  - Accounts always serialize their IDL discriminator and `UnmarshalWithDecoder` rejects data with a different one.
  - Instructions with a constant discriminator (not an argument) or a field discriminator at a non-zero offset are encoded, validated and dispatched like leading field discriminators.
  - The instruction decoder is registered with solana-go at package init, so `ag_solanago.DecodeInstruction` works for the default `ProgramID` without calling `SetProgramID`.
  
  ### Generated code hygiene
  
  The generated packages pass `golangci-lint` with `errcheck`, `govet`, `staticcheck`, `revive`, `gocritic`, `gosec`, `perfsprint` and friends enabled (generated-file exclusions disabled): `SetProgramID` now returns the registration error, `Instruction_N_Count` is a constant, `any` replaces `interface{}`, codec methods use `if err := ...; err != nil` and `errors.New` for constant messages, and every exported symbol carries a doc comment (IDL docs are used for types and accounts when present). Program error constants keep their `<Name>Error` form on purpose, matching the solana-go clients users already know.
  
  Generated Go API changes: `SetProgramID` returns `error`; `InstructionImplDef` (an `ag_binary.VariantDefinition` that could never hold explicit IDL discriminators) is removed; `Build()`/`ValidateAndBuild()` are pointer-receiver methods; `GetAccounts()` returns a copy with optional-account placeholders applied. Enum default values on data-enum arguments remain unsupported.

- [#74](https://github.com/codama-idl/renderers-go/pull/74) [`6a2db48`](https://github.com/codama-idl/renderers-go/commit/6a2db4857557a03e760961e54e321b2357745a5d) Thanks [@sonicfromnewyoke](https://github.com/sonicfromnewyoke)! - Dependency refresh and generated go.mod:
  
  - New `goModule` option: the render visitor emits a `go.mod` for the generated package, with the Go dependency versions pinned in one place (`goMod.njk`); the e2e projects' go.mod files are now rendered from that same template.
  - Generated clients build against `github.com/gagliardetto/solana-go` v1.23.0.
  - Updated npm dependencies (`@codama/*` 1.10, `@solana/codecs-strings` ^8.2.0, and dev tooling), including support for codama's optional node collections and `injectedValueNode` (rendered via its fallback value).
